## Storage, Authorization and Recovery

022 adds immutable history and execution event tables, mutable fenced execution
state and an immutable artifact/intent. It seeds no roles and modifies no prior
migration. Authorization is checked before history queries/counts and again on
each executor claim. Current In Use authorization is capability-wide; there is
no owner-private OR ACL to bypass. History/reuse is limited to the trusted
provider/tenant/object ID derived from the current authorized record. No public
endpoint accepts a successful step outcome or a human identity from a Worker.

Reuse requires unchanged environment, network, IP, hostname, service ID, OS name,
OS version and aspect ID; the first five must exist. Source observation must be
within 24 hours, review within 30 days, neither in the future, and the previous
source observation must have been current when reviewed. Missing old provenance
is shown rather than invented. Accepting actor/time is always server stamped.
Copied values are snapshots: later edits to the source answer do not propagate.

Intent, artifact and first audit/event commit atomically before Hangfire enqueue.
Startup/minutely recovery uses the existing Worker. Duplicate command IDs and
different IDs for the same active OR/snapshot do not create another operation.
Each step has a token/revision/expiry lease. Old/out-of-order results are rejected.
Expired mutation leases become Unknown; only read steps can be requeued. An
upload response, attachment readback, BPM acknowledgement and OR readback are
separate. Revocation/source drift stops new steps without deleting earlier effects.
Business report version is not incremented by step journal writes. Historical
blocked completion intents are never recovered into executable work.

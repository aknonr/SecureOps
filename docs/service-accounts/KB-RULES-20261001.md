## Oracle correction (`de69266`)

The approved 2026-10-01 decision covers SQL-team routing only. It does not establish that Oracle never needs a service
account. Until an explicit Oracle business rule is approved, `KB-VT-ORACLE` recommends **manual review** with an
"unverified" reason, never removal or deletion, and adds no handover target (so no split). New conformance
`ManualReviewPending` ("Manuel inceleme bekliyor") applies to every path without an approved rule (Oracle, IIS
application pool, other) when no review/evaluation request is open; it is listed for review and **not** counted as
against the rule. `NoServiceAccountNeeded` remains reserved; no current rule produces it. Rule set version
`kb-2026-08-11+karar-2026-10-01+r2`; the report list and export section is "İncelenecek hesaplar".

## Duplicate routing fix (`e17f957`)

Routing previously checked only its own source key, so an account with a manually created gMSA request (for example from
the recommendation button) received a second request on the next SQL-team list. Routing now skips any account with a
gMSA transition or any GmsaHandover/GmsaConversion request (open or closed). Negative control: with the check removed,
`ServiceAccountKbPersistedAccessSqlTests` fails (3 routed rows instead of 2).

## 1. Ön kontrol (salt okunur — hiçbir şey değiştirmez)

Hedef veritabanında çalıştırın. Her satırın beklenen değeri yanındadır.

```sql
SET NOCOUNT ON;
SELECT DB_NAME() AS Veritabani, CONVERT(varchar(40), SERVERPROPERTY('ProductVersion')) AS SqlSurumu;

-- Ön koşullar: dördü de 'var' olmalı
SELECT
  CASE WHEN OBJECT_ID(N'svcacct.ScopeGrants', N'U') IS NULL THEN 'EKSIK' ELSE 'var' END AS [025 ScopeGrants],
  CASE WHEN OBJECT_ID(N'svcacct.WorkRequests', N'U') IS NULL THEN 'EKSIK' ELSE 'var' END AS [025 WorkRequests],
  CASE WHEN OBJECT_ID(N'svcacct.AccountUsages', N'U') IS NULL THEN 'EKSIK' ELSE 'var' END AS [026 AccountUsages],
  CASE WHEN DATABASE_PRINCIPAL_ID(N'svcacct_api_runtime') IS NULL THEN 'EKSIK' ELSE 'var' END AS [API rolü];

-- Durum: 029 ve 030 henüz 'uygulanmamış' olmalı (ikisi de 'uygulanmış' ise yeniden çalıştırmayın)
SELECT
  CASE WHEN COL_LENGTH(N'svcacct.ScopeGrants', N'IsBootstrap') IS NULL THEN 'uygulanmamış' ELSE 'uygulanmış' END AS [029],
  CASE WHEN OBJECT_ID(N'svcacct.UsageScans', N'U') IS NULL THEN 'uygulanmamış' ELSE 'uygulanmış' END AS [030];

-- Karşılaştırma için: uygulamadan önce ve sonra aynı olmalı
SELECT COUNT(*) AS KapsamSatiri, SUM(CASE WHEN RevokedAt IS NULL THEN 1 ELSE 0 END) AS Aktif FROM svcacct.ScopeGrants;
SELECT name, is_not_trusted, definition FROM sys.check_constraints WHERE parent_object_id = OBJECT_ID(N'svcacct.ScopeGrants');
```

Beklenen: ön koşulların hepsi `var`; `029` ve `030` `uygulanmamış`; `CK_SaScopeGrants_NoSelfGrant` tanımı `([UserId]<>[GrantedBy])`,
`is_not_trusted = 0`. Bir ön koşul `EKSIK` ise durun; bu belgedeki adımlar o durumda uygulanmaz.

## 2. Uygulama komutları

`:r` satırları göreli yol kullandığı için **029 ve 030 `sql\migrations` klasöründen**, `sqlcmd` ile (SSMS'te SQLCMD Mode) ve
`-I -b` ile çalıştırılır. Her komuttan sonra çıkış kodu 0 olmalı; değilse sonrakine geçmeyin.

```powershell
cd <repo>\sql\migrations
sqlcmd -S <sunucu> -d <veritabanı> -E -I -b -i 029-service-account-scope-bootstrap.sql
sqlcmd -S <sunucu> -d <veritabanı> -E -I -b -i 030-service-account-usage-scans.sql

cd ..\pending\service-accounts
sqlcmd -S <sunucu> -d <veritabanı> -E -I -b -i SA-004-API-permissions.sql
```

Sıra şema → uygulama sürümüdür. 029 ve 030 eski API sürümüyle uyumludur (eski sürüm `IsBootstrap` yazmaz, varsayılan 0 olur;
yeni tabloları kullanmaz). Yeni API/UI sürümü 029 olmadan ilk-kapsam özelliğini kapalı tutar ve bilgi metni gösterir,
030 olmadan tarama sekmesinde "Veritabanı güncellemesi 030 uygulanmamış" der; diğer işlevler çalışır.

## 3. Uygulama sonrası doğrulama (salt okunur)

```sql
SET NOCOUNT ON;
-- 029: ön kontroldeki sayılar aynı; mevcut satırların hepsi IsBootstrap = 0 (ilk-kurulum yapılmadıysa)
SELECT COUNT(*) AS KapsamSatiri, SUM(CAST(IsBootstrap AS int)) AS BootstrapSatiri FROM svcacct.ScopeGrants;
SELECT name, is_not_trusted FROM sys.check_constraints WHERE name = N'CK_SaScopeGrants_NoSelfGrant';   -- is_not_trusted = 0
SELECT name, is_unique FROM sys.indexes WHERE name = N'UX_SaScopeGrants_OneBootstrap';                  -- 1 satır
-- 030: beş tablo, her birinde değişmezlik tetikleyicisi, güvenilir kısıtlar
SELECT COUNT(*) AS Tablo FROM sys.tables WHERE name LIKE N'UsageScan%';                                  -- 5
SELECT COUNT(DISTINCT parent_id) AS TetikleyiciliTablo FROM sys.triggers
  WHERE parent_id IN (SELECT object_id FROM sys.tables WHERE name LIKE N'UsageScan%');                  -- 5
SELECT COUNT(*) AS GuvenilmeyenKisit FROM sys.check_constraints
  WHERE is_not_trusted = 1 AND parent_object_id IN (SELECT object_id FROM sys.tables WHERE name LIKE N'UsageScan%');  -- 0
-- İzinler: yalnız svcacct_api_runtime, yalnız SELECT ve INSERT (10 satır); başka rol/kullanıcı yok
SELECT OBJECT_NAME(major_id) AS Tablo, USER_NAME(grantee_principal_id) AS Alan, permission_name, state_desc
FROM sys.database_permissions WHERE class = 1 AND OBJECT_NAME(major_id) LIKE N'UsageScan%' ORDER BY 1, 3;
```

Ardından `029` ve `030` komutlarını bir kez daha çalıştırmak **reddedilmelidir** ("already applied"); bu beklenen davranıştır,
veri değiştirmez.

## 4. Geri dönüş

1. **Birincil yol:** DBA'nın uygulamadan önce aldığı kendi yedeğinden dönüş (DBA süreci).
2. **030 (yalnız hiç tarama yüklenmediyse):** tablolar boşsa bağımlılık sırasıyla düşürülür; API rolünün izinleri tablolarla
   birlikte gider. Satır varsa düşürmeyin: kayıtlar delil niteliğindedir ve tetikleyiciyle korunur.

   ```sql
   DROP TABLE svcacct.UsageScanDecisions; DROP TABLE svcacct.UsageScanLinks; DROP TABLE svcacct.UsageScanItems;
   DROP TABLE svcacct.UsageScanServers;  DROP TABLE svcacct.UsageScans;
   ```
   Tabloları bırakıp yalnız erişimi kapatmak isterseniz: `REVOKE SELECT, INSERT ON OBJECT::svcacct.UsageScans FROM svcacct_api_runtime;`
   (beş tablo için ayrı ayrı). Eski API sürümü bu tabloları kullanmaz; durmaları zararsızdır.
3. **029 (yalnız `IsBootstrap = 1` satırı yokken):** özgün kısıt geri konur. İlk-kurulum satırı oluşmuşsa kısıt geri
   konamaz; sütunu bırakın (eski API sürümü için zararsızdır).

   ```sql
   DROP INDEX UX_SaScopeGrants_OneBootstrap ON svcacct.ScopeGrants;
   ALTER TABLE svcacct.ScopeGrants DROP CONSTRAINT CK_SaScopeGrants_NoSelfGrant;
   ALTER TABLE svcacct.ScopeGrants WITH CHECK ADD CONSTRAINT CK_SaScopeGrants_NoSelfGrant CHECK (UserId <> GrantedBy);
   ALTER TABLE svcacct.ScopeGrants DROP CONSTRAINT DF_SaScopeGrants_IsBootstrap;
   ALTER TABLE svcacct.ScopeGrants DROP COLUMN IsBootstrap;
   ```

Yukarıdaki 030 ve 029 geri alma komutları sentetik kopyada bir işlem içinde denenip geri alındı (`ROLLBACK`); gerçek veritabanında denenmedi.

## How the UI is built

Paths are relative to `src/SecureOps.Ui/`.

- Blazor Server on .NET 8 with MudBlazor 6.16 (support for v6 has ended; a v9 migration is application-wide work — see the MudBlazor assessment in the UI README).
- Pages talk to the API only through typed clients in `Services/` (`I*ApiClient`), which throw `SecureOpsApiException` carrying a `UiProblem`. Render problems with `SoProblemPanel`; never show raw exception text.
- Access: pages are `@attribute [Authorize]` and read `ICurrentAccessProvider` → `AccessSnapshot.Can(Capabilities.X)` to decide what to show. The API re-checks every call.
- Shared building blocks in `Shared/Components/So*` (page header, problem, empty, loading, status badge, field grid, confirmations). Theme: `Shared/SecureOpsTheme.cs` plus tokens in `wwwroot/css/secureops-theme.css`; new styling goes in scoped `.razor.css` using those tokens.
- `Pages/_Host.cshtml` holds small native script for things Blazor cannot do safely (opening several links on one trusted click, MudBlazor 6 accessibility bridges). Keep it minimal and documented; it is not a place for feature logic.
- Forms: Blazor/MudBlazor components and `EditForm`; dialogs keep the operator's draft until the server confirms, and a version conflict (409) offers an explicit reread, never an automatic retry.

## UI rules that come from the domain

- Audit screens are "operational audit": filter by action and time window, sort by time, no per-operator rankings or comparisons.
- Status words must match evidence: "configured" is not "healthy", "requested" is not "opened", a partial result says it is partial.
- Do not invent fields, counts or reasons the contract does not return; record the gap in `docs/26-ui-backend-contract-gaps.md`.
- Turkish UI text, operator vocabulary from `CLAUDE.md`.
